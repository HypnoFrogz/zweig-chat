# Nebenan

Корпоративный мессенджер, который разворачивается в контуре компании: чаты в реальном времени, видеозвонки, файловое хранилище и админ-панель. Переписка, документы и встречи не покидают ваш сервер. Один и тот же веб-интерфейс работает в браузере, как PWA и как десктопное приложение (Windows `.exe`).

Построен на **FastAPI**, **vanilla JavaScript**, **LiveKit**, **Electron** и **Docker**.

Открытый исходный код под лицензией **[AGPL-3.0](LICENSE)** — разворачивайте у себя, изучайте, дорабатывайте.

## Фирменный стиль и палитра

Nebenan использует тёплую двухтемную палитру на CSS-переменных. Amber и Forest меняются ролями между темами, что задействует все фирменные цвета в каждой.

| Цвет | HEX | Роль |
|------|-----|------|
| **Terracotta** | `#d97b4f` | (историч.) тёплый акцент |
| **Amber** | `#e0a458` (свет) · `#e8a93f` (уведомл.) | акцент/кнопки в светлой теме, бейджи непрочитанных |
| **Forest** | `#3a5a48` | акцент/кнопки в тёмной теме, статусы «онлайн», навигация |
| **Cream** | `#f5eee3` | фон интерфейса в светлой теме |
| **Charcoal** | `#33302c` | фон в тёмной теме, основной текст в светлой |

- **Тёмная тема** (по умолчанию): фон Charcoal, акцент Forest, уведомления Amber, текст cream.
- **Светлая тема**: фон Cream, акцент Amber, статусы Forest, текст Charcoal.
- Читаемость текста на кнопках обеспечивает переменная `--on-accent`.

## Возможности

### Сообщения
- Обмен сообщениями в реальном времени через WebSocket
- Публичные и приватные каналы, личные сообщения (ЛС)
- Категории/папки для организации чатов
- Редактирование и удаление сообщений
- Ответы и треды
- Реакции эмодзи
- Упоминания `@логин`
- Статусы прочтения (галочки)
- Индикатор набора текста
- Закреплённые сообщения
- Пересылка сообщений
- Полнотекстовый поиск по каналам
- Счётчики непрочитанного (бейджи Amber)

### Видеозвонки
- Аудио- и видеозвонки на базе LiveKit (WebRTC)
- Комнаты до 10 участников
- Управление камерой и микрофоном
- Приглашение конкретных пользователей
- Таймер длительности
- TURN-сервер для обхода NAT

### Файловый менеджер
- Персональное хранилище для каждого пользователя
- Папки, загрузка нескольких файлов с автопереименованием
- Отправка файлов в чат, копирование ссылки
- Просмотр, скачивание, переименование, удаление
- Виды «список» и «сетка», превью изображений/видео

### Профили
- Отображаемое имя (кириллица поддерживается), никнейм, статус
- Загрузка аватара (PNG, JPG, GIF, WebP, до 5 МБ)
- Синхронизация профиля в реальном времени
- Онлайн/оффлайн со временем последнего визита

### Админ-панель
- Создание пользователей (логин / пароль / отображаемое имя)
- **Массовый импорт пользователей из Excel/CSV** + скачивание шаблона
- Выдача и снятие роли администратора
- Блокировка/разблокировка, сброс пароля, удаление
- Просмотр обратной связи

### Настройки
- Тёмная / Светлая тема
- Русский / Английский язык (i18n)
- Настройки сохраняются между сессиями и синхронизируются с сервером

> Модуль задач (*ChaosTracker*) присутствует в кодовой базе, но временно **скрыт** в интерфейсе.

## Клиенты

| Клиент | Технология | Статус |
|--------|-----------|--------|
| **Веб / PWA** | `frontend/` (vanilla JS) | Мессенджер на вашем домене |
| **Десктоп (Windows `.exe`)** | `desktop/` (Electron, оборачивает `frontend/`) | Поддерживается — 1:1 веб-версия |

Десктоп и веб используют **один и тот же** `frontend/`, поэтому выглядят идентично.

> Мобильные приложения (Android / iOS) в открытый код не входят — распространяются отдельно.

### Домен

| Адрес | Что отдаёт |
|-------|-----------|
| `chat.example.com` | веб-клиент + `/api` + WebSocket + `/uploads` + `/livekit` |

Домен мессенджера должен A-записью указывать на сервер — сертификат выпускается через `init-ssl.sh`.

## Архитектура

```
Клиент: браузер / PWA / Electron (.exe)
    |  (вводит адрес сервера → API/WS/медиа идут туда)
    v
  Nginx (:80, :443)
    |--- /               --> Статический фронтенд (HTML/CSS/JS)
    |--- /api/           --> FastAPI бэкенд (:8000)  [CORS включён]
    |--- /api/ws/        --> WebSocket (сообщения, presence)
    |--- /livekit/       --> LiveKit сервер (:7880)
    |--- /uploads/       --> Раздача файлов и аватаров
    v
  Бэкенд (FastAPI)
    |--- SQLite (aiosqlite, WAL)
    |--- Файловое хранилище (/app/uploads)
    |--- LiveKit API (генерация токенов)
    v
  LiveKit Server (WebRTC медиа UDP :7882-7892, TURN :3478/:5349)
```

Десктопное приложение поднимает локальный статический сервер для `frontend/` и подключается к выбранному пользователем серверу кросс-доменно (см. [Вход по адресу сервера](#вход-по-адресу-сервера)).

## Быстрый старт (Docker, продакшн)

### Требования
- Docker и Docker Compose
- Доменное имя (для SSL/WebRTC в браузере)
- Открытые порты (см. [ниже](#порты-и-файервол))

### 1. Клонировать

```bash
git clone https://github.com/HypnoFrogz/nebenan-chat.git
cd nebenan
```

### 2. Настроить секреты (`.env`)

Секреты **не** хранятся в репозитории. Скопируйте шаблон и заполните своими значениями:

```bash
cp .env.example .env
```

Сгенерируйте свежие значения (см. [Переменные окружения](#переменные-окружения)). Для VAPID:

```bash
npx web-push generate-vapid-keys
```

### 3. Настроить LiveKit

```bash
cp livekit/livekit.yaml.example livekit/livekit.yaml
```

В `livekit/livekit.yaml` укажите свой домен и пару ключ/секрет (должны совпадать с `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` в `.env`).

### 4. Домен в Nginx

Конфиги уже настроены на **`example.com`** (`nginx/nginx.conf`, `nginx/nginx-ssl.conf`, `init-ssl.sh`, `LIVEKIT_PUBLIC_URL` в `docker-compose.yml`). Если домен другой — замените его в этих файлах:

```nginx
server_name ваш-домен;
ssl_certificate     /etc/letsencrypt/live/ваш-домен/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/ваш-домен/privkey.pem;
```

**DNS.** Домен мессенджера должен A-записью указывать на сервер:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | `chat` | публичный IP сервера |

Проверить перед выпуском сертификата:
```bash
nslookup chat.example.com
```

### 5. Получить SSL-сертификат

```bash
mkdir -p certbot/conf certbot/www
docker run --rm -p 80:80 \
  -v $(pwd)/certbot/conf:/etc/letsencrypt \
  -v $(pwd)/certbot/www:/var/www/certbot \
  certbot/certbot certonly --standalone -d ваш-домен.ru
```

### 6. Запустить

```bash
docker compose up -d --build
```

Приложение будет доступно по адресу `https://ваш-домен.ru`.
Логин по умолчанию: **admin** / значение `ADMIN_PASSWORD` из `.env` (смените сразу).

## Локальный запуск и разработка

Полный прод-стек (nginx + livekit + certbot) требует реального домена и сертификатов. Для локальной проверки удобнее поднять только бэкенд.

### Вариант A — только бэкенд через Docker (рекомендуется для теста)

В репозитории можно создать локальный override, который пробрасывает порт бэкенда напрямую (в обход nginx/livekit):

```yaml
# docker-compose.override.yml  (gitignored, авто-подхватывается)
services:
  backend:
    ports:
      - "8000:8000"
```

```bash
docker compose up -d --build backend
curl http://localhost:8000/api/health      # {"status":"ok"}
```

Затем в клиенте (веб/exe) введите адрес сервера **`http://localhost:8000`** и войдите как **admin / admin**.

> В этом режиме файлы/аватары (`/uploads/...`) не отображаются — их раздаёт nginx. Текстовые чаты и админка работают полностью.

### Вариант B — бэкенд через uvicorn (без Docker)

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### Фронтенд отдельно

```bash
cd frontend
python -m http.server 5500
# откройте http://localhost:5500  → введите адрес бэкенда на экране входа
```

## Десктопное приложение (.exe)

Десктоп-клиент — это Electron-обёртка, которая **вшивает `frontend/`** и показывает ровно ту же веб-версию.

### Сборка

```bash
cd desktop
npm install
npm run dist
```

Результат: `desktop/dist/Nebenan-win32-x64/Nebenan.exe` (portable, подпись не требуется).

### Как это работает
- При запуске поднимается локальный статический сервер на фиксированном loopback-порту (`17673`+), что даёт стабильный `http`-origin — сохраняются адрес сервера и токены между запусками, работает service worker.
- Фронтенд обращается к серверу, введённому пользователем, **кросс-доменно** (бэкенд разрешает это через CORS).
- Внешние ссылки открываются в системном браузере.

> Изменения во `frontend/` попадают в exe только после **пересборки** (`npm run dist`). В веб-версии они применяются сразу.

## Федерация серверов

Два независимых сервера Nebenan можно связать, чтобы их пользователи могли общаться между собой. Связывание подтверждают **администраторы обоих серверов**.

### Настройка
В `.env` каждого сервера обязателен его собственный публичный домен — без него федерация выключена (сервер не может доказать, кто он):

```env
SERVER_DOMAIN=chat.example.com
FEDERATION_ALLOW_HTTP=        # только для отладки; в проде оставить пустым
```

### Как это работает
1. Админ сервера **А** в админ-панели → «Серверы» → вводит домен сервера **Б** → «Добавить сервер».
2. А отправляет заявку на Б с одноразовым токеном.
3. **Б не доверяет содержимому запроса**: он сам обращается к `https://А/api/federation/verify` и проверяет, что А действительно выдал этот токен именно для Б. Так подтверждается владение доменом — подделать заявку от чужого имени нельзя.
4. Админам Б прилетает уведомление, заявка появляется в админке со статусом «Входящая заявка» и кнопками **Добавить** / **Отклонить**.
5. При подтверждении Б генерирует `shared_secret`, передаёт его А, и оба ставят статус «Подключён». Этим секретом подписываются последующие server-to-server запросы.

⚠️ Федерация работает **только по HTTPS** — `shared_secret` передаётся между серверами, и по plain HTTP он уйдёт открытым текстом. Поэтому связать два локальных сервера по `http://` можно только с `FEDERATION_ALLOW_HTTP=1` и исключительно для отладки.

### Статусы
| Статус | Значение |
|--------|----------|
| Ожидает подтверждения | мы отправили заявку, ждём решения их админа |
| Входящая заявка | нас просят подключиться — нужно решение нашего админа |
| Подключён | связь установлена |
| Отклонён | одна из сторон отказала |

## Вход по адресу сервера

Как в Mattermost Desktop, вход — двухшаговый:

1. **Адрес сервера** — IP или домен (например `chat.example.com` или `192.168.1.10`). Адрес проверяется через `GET /api/health` и сохраняется.
2. **Логин и пароль**.

После подключения все запросы (`/api`, WebSocket, `/uploads`) идут на выбранный сервер. Пустой адрес = тот же origin, что и страница. Это делает один и тот же билд фронтенда пригодным для любого сервера Nebenan (нужен включённый CORS — он есть по умолчанию).

## Переменные окружения

Задаются в `.env` (см. `.env.example`). Ротируйте все значения перед деплоем.

| Переменная | Описание | Примечание |
|------------|----------|------------|
| `SECRET_KEY` | Ключ подписи JWT | длинная случайная строка |
| `ADMIN_USERNAME` | Логин администратора (создаётся при первом запуске) | по умолчанию `admin` |
| `ADMIN_PASSWORD` | Пароль администратора | задать в `.env` |
| `LIVEKIT_API_KEY` | API-ключ LiveKit | совпадает с `livekit.yaml` |
| `LIVEKIT_API_SECRET` | Секрет LiveKit | совпадает с `livekit.yaml` |
| `LIVEKIT_URL` | Внутренний WS-адрес LiveKit | `ws://livekit:7880` |
| `LIVEKIT_PUBLIC_URL` | Публичный WSS-адрес LiveKit | `wss://ваш-домен/livekit/` |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | Ключи Web Push | сгенерировать заново |
| `VAPID_EMAIL` | Контакт для Web Push | `mailto:...` |
| `FIREBASE_CREDENTIALS` | Путь к firebase-service-account.json | опционально; без него push отключён |
| `UPLOAD_DIR` / `DATA_DIR` | Пути хранения | `/app/uploads`, `/app/data` |
| `CORS_ORIGINS` | Разрешённые origin через запятую | по умолчанию `*` |

## Порты и файервол

| Порт | Протокол | Сервис |
|------|----------|--------|
| **80** | TCP | HTTP (редирект на HTTPS / ACME) |
| **443** | TCP | HTTPS (веб + API) |
| **7880** | TCP | LiveKit WebSocket сигнализация |
| **7881** | TCP | LiveKit TCP (резервный медиа-канал) |
| **7882–7892** | UDP | LiveKit WebRTC медиа (RTP) |
| **3478** | UDP | TURN (обход NAT) |
| **5349** | TCP | TURN через TLS |

### Linux (UFW)

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 7880/tcp
sudo ufw allow 7881/tcp
sudo ufw allow 7882:7892/udp
sudo ufw allow 3478/udp
sudo ufw allow 5349/tcp
```

### Windows Server (PowerShell от администратора)

```powershell
New-NetFirewallRule -DisplayName "Nebenan HTTP"       -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan HTTPS"      -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan LiveKit WS" -Direction Inbound -Protocol TCP -LocalPort 7880 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan LiveKit TCP" -Direction Inbound -Protocol TCP -LocalPort 7881 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan LiveKit UDP" -Direction Inbound -Protocol UDP -LocalPort 7882-7892 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan TURN UDP"   -Direction Inbound -Protocol UDP -LocalPort 3478 -Action Allow
New-NetFirewallRule -DisplayName "Nebenan TURN TLS"   -Direction Inbound -Protocol TCP -LocalPort 5349 -Action Allow
```

## Админ-панель

Доступна пользователям с ролью `admin` (кнопка в сайдбаре и в настройках).

### Создание пользователя
Поля: **Логин**, **Пароль**, **Отображаемое имя**.

- **Логин** используется для входа и для упоминаний `@` в чатах. Подсветка упоминаний работает по `\w`, поэтому логин ограничен **латиницей, цифрами и `_`** (2–32 символа).
- **Отображаемое имя** — произвольное, **кириллица поддерживается**.

### Импорт из Excel / CSV
Кнопка **«Импорт из Excel»** принимает `.xlsx` или `.csv`. Кнопка **«Шаблон»** скачивает готовый `.xlsx`.

Ожидаемые столбцы (заголовки распознаются на русском и английском):

| Логин | Пароль | Отображаемое имя | Роль |
|-------|--------|------------------|------|
| ivan | changeme123 | Иван Ковач | user |
| anna_k | changeme123 | Анна | admin |

После импорта показывается сводка: **создано / пропущено (уже существуют) / ошибки** с построчными сообщениями.

### Роли
Кнопка со щитом в строке пользователя выдаёт (`add_moderator`) или снимает (`remove_moderator`) роль администратора. Свою собственную роль изменить нельзя.

## База данных

SQLite в режиме WAL (асинхронно через aiosqlite). Схема мигрируется автоматически при запуске.

| Таблица | Описание |
|---------|----------|
| `users` | Аккаунты, профили, роли |
| `user_sessions` | Refresh-сессии (отзыв при блокировке/сбросе) |
| `channels` · `channel_members` | Каналы и членство |
| `messages` · `message_reads` · `message_reactions` | Сообщения, прочтения, реакции |
| `active_calls` | Активные видеозвонки |
| `preferences` | Тема/язык |
| `chat_folders` | Категории чатов |
| `user_devices` | Токены устройств для push |
| `feedback` | Обратная связь |

Бэкап SQLite из тома:

```bash
docker cp nebenan-backend:/app/data/chaoshelper.db ./backup.db
```

## Безопасность

- **Все секреты вынесены в `.env`** (gitignored). В репозитории — только `.env.example` с плейсхолдерами.
- Значения из легаси-истории считаются **скомпрометированными** — сгенерируйте новые `SECRET_KEY`, `ADMIN_PASSWORD`, LiveKit key/secret и **новую пару VAPID** перед деплоем.
- SSL обязателен для WebSocket и WebRTC в браузерах.
- JWT: короткоживущий access + refresh; сессии отзываются при блокировке и сбросе пароля.
- Пароли хешируются bcrypt.
- Загрузки изолированы по пользователям (без обхода директорий).
- Операции управления пользователями требуют роли `admin`.
- CORS по умолчанию `*` (аутентификация по Bearer-токену, не по кукам); в проде ограничьте через `CORS_ORIGINS`.
