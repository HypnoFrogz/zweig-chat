# Боты и входящие вебхуки

Два способа автоматизировать переписку:

- **Входящий вебхук** — без программирования. Админ создаёт адрес для канала,
  внешний сервис (CI, мониторинг, CRM) отправляет туда POST с текстом, и
  сообщение появляется в канале от имени бота.
- **Бот** — программа, которая читает сообщения в своих каналах и личке и
  отвечает. Работает через Bot API по токену.

Оба создаются в админке: «Админка → Боты».

## Входящий вебхук

1. «Админка → Боты → Входящие вебхуки»: выбрать канал, при желании — бота,
   от имени которого писать (по умолчанию общий бот «Вебхук»), название.
2. Скопировать адрес — он показывается один раз. Адрес — как пароль.
3. Отправить сообщение:

   ```bash
   curl -X POST https://chat.example.ru/api/hooks/zh_... \
        -H 'Content-Type: application/json' \
        -d '{"text": "Сборка #128 прошла ✅"}'
   ```

Принимается JSON с полем `text` (также `message` или `content`),
Slack-совместимая форма с `payload`, и просто текст в теле запроса.

Пример для GitLab CI:

```yaml
notify:
  stage: .post
  script:
    - 'curl -s -X POST "$ZWEIG_HOOK" -H "Content-Type: application/json"
       -d "{\"text\": \"$CI_PROJECT_NAME: пайплайн $CI_PIPELINE_ID — $CI_JOB_STATUS\"}"'
```

## Бот

1. «Админка → Боты»: логин (латиница, цифры, `_`), имя, описание. Токен
   `zb_…` показывается один раз; потеряли — «Новый токен» (старый сразу
   перестаёт действовать).
2. Добавить бота в нужные каналы: кнопка «Добавить в канал» или как обычного
   участника из канала. Написать боту в личку может любой.
3. Запустить пример: [examples/zweig_bot.py](examples/zweig_bot.py).

### Bot API

Все запросы — с заголовком `Authorization: Bearer zb_…`.

| Запрос | Что делает |
|---|---|
| `GET /api/bot/me` | кто я |
| `GET /api/bot/channels` | каналы, где состоит бот |
| `POST /api/bot/channels/{slug}/messages` `{text, reply_to?}` | написать в канал |
| `PUT /api/bot/channels/{slug}/messages/{id}` `{text}` | исправить своё сообщение |
| `DELETE /api/bot/channels/{slug}/messages/{id}` | удалить своё сообщение |
| `POST /api/bot/direct` `{username, text}` | написать в личку тому, кто уже писал боту |
| `GET /api/bot/updates?offset=&timeout=` | получить новые сообщения (долгий опрос) |

**Обновления.** `GET /api/bot/updates` ждёт до `timeout` секунд (до 50) и
отдаёт список:

```json
[{"update_id": 42, "type": "message",
  "message": {"id": "…", "channel": {"slug": "ci", "name": "Сборки", "type": "public"},
              "sender": "anna", "sender_name": "Анна", "type": "text",
              "text": "/ping", "file": null, "reply_to": null,
              "timestamp": "2026-10-22T10:00:00+00:00"}}]
```

Следующий запрос — с `offset` = последнему `update_id`: всё до него
включительно сервер удаляет. Очередь хранит до 1000 обновлений на бота.

**Вебхук бота.** Если в админке у бота указан адрес, каждое обновление ещё и
отправляется туда POST-запросом (тот же JSON, один объект). Очередь для
опроса при этом тоже пополняется — можно использовать оба способа.

### Ограничения

- Бот видит только каналы, куда его добавили, и личку, которую ему написали;
  первым в личку бот не пишет.
- Не больше 30 сообщений в минуту на бота (и на каждый вебхук) — иначе 429.
- Бот не входит паролем, его роль не меняется на «пользователя».
- Все действия бота пишутся в журнал `bot_audit`.
- В общих каналах с другими серверами (федерация) сообщения бота доходят как
  обычные.

Пока нет: команд через `/` с подсказками и кнопок под сообщениями — они в
плане (README, пункт 5).
