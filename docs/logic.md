# Логика релизной подготовки

## Правила
- Сборка релиза выполняется только после успешного `flutter pub get`.
- Для Google Play используется `flutter build appbundle --release`.
- Все секреты подписи хранятся локально и исключаются из git.

## Проверки
- Наличие `google-services.json` в `mobile/android/app/`.
- Валидная release-конфигурация подписи (`signingReport` показывает `Config: release`).
- Наличие итоговых артефактов APK/AAB в `mobile/build/app/outputs/`.

## Логика авторизации и сессий
- Клиент использует `access_token` для API-запросов и websocket-подключений.
- При `401` клиент сначала пытается обновить access через `refresh_token`, и только при неуспехе очищает сессию.
- Сетевые ошибки и временные ошибки backend (`5xx`) не должны вызывать удаление токенов.
- Refresh-сессия хранится на сервере в `user_sessions` и может быть отозвана админом.
- Сброс пароля/блокировка пользователя немедленно инвалидирует все его refresh-сессии.
- Для mobile API endpoint должен задаваться через `--dart-define=API_BASE_URL`, чтобы prod/stage сборки не расходились по backend.
- Если `API_BASE_URL` задан без суффикса `/api`, клиент добавляет его автоматически перед инициализацией HTTP-клиента.

## Логика звонков
- Новый адресный поток звонков использует `call_id` и endpoint'ы `calls/*`.
- Cold-call push отправляется только целевому абоненту (`callee`) с TTL (`expires_at`).
- По умолчанию звонок стартует как аудио (`mode=audio`): камера выключена, speaker выключен.
- Во время звонка пользователь вручную включает/выключает видео и громкую связь.
- Если входящий вызов не принят до `expires_at`, звонок должен переходить в `missed`.
- Перед созданием нового адресного звонка backend обязан сначала перевести протухшие `ringing` записи в `missed`, чтобы исключить ложный `busy`.
- Backend также закрывает устаревшие `active` звонки по таймауту `CALL_ACTIVE_STALE_SEC`, чтобы не блокировать новые вызовы.
- Backend периодически выполняет self-healing cleanup (`CALL_CLEANUP_INTERVAL_SEC`) и запускает cleanup при старте (`CALL_CLEANUP_ON_STARTUP=true`).
- Завершённые/пропущенные звонки без архивации удаляются по retention-окну `CALL_RETENTION_DAYS` (по умолчанию 5 дней).
- Клиент при ошибке старта звонка обязан показывать человеку причину из backend (`detail`), а не только общий fallback.
- Перед websocket connect/reconnect mobile-клиент обязан обновить access-token через refresh-сессию, иначе presence становится асимметричным.
- При принятии входящего звонка mobile обязан использовать параметры подключения LiveKit из ответа `calls/answer`, а не из кешированного invite payload.
- Proxy `/livekit/` должен обеспечивать прямой websocket upgrade без rewrite-цепочки, чтобы исключить nginx 500 на connect.
- При ошибке отправки websocket backend обязан немедленно удалить проблемный сокет, чтобы `is_online()` не оставался ложноположительным.
- Для адресного потока `calls/*` backend отправляет call-push wake fallback (`CALL_PUSH_ALWAYS`) для cold-call сценариев при фоне/офлайне callee.
- Mobile должен показывать incoming call notification/ringtone по FCM `call_invite` в фоне, а при открытии приложения восстанавливать in-app incoming overlay через pending invite.
- Для входящего `call_invite` push не должен создавать звук сам: локальное уведомление silent, звуковой сигнал создаётся только ringtone-механизмом клиента.
- При активном входящем звонке звуки новых сообщений должны подавляться, чтобы не перебивать рингтон.
- Android release обязан сохранять generic signatures для библиотек нотификаций, иначе `cancelNotification` может падать с `TypeToken`-ошибкой.
- Mobile должен блокировать повторный accept одного и того же `call_id`, чтобы исключить конфликтный `409` на `calls/answer`.
- При получении `call_invite` через FCM мобильный клиент должен сохранять invite в persistent storage и при старте приложения восстанавливать incoming overlay, даже если Android не показал full-screen/heads-up UI.
- Pending `call_invite` должен удаляться при accept/reject/end, чтобы не показывать устаревшее приглашение повторно.
- При получении `call_ended` и `call_answered` мобильный клиент должен закрывать incoming overlay по совпадению `call_id` (приоритетно), чтобы избежать ложного закрытия по `channel_slug`.
- Мобильный клиент должен иметь локальный TTL fallback по `expires_at`: если серверное событие завершения не пришло вовремя, incoming overlay и рингтон очищаются автоматически.
- Web-клиент должен использовать ту же модель: закрывать incoming UI только при совпавшем `call_id`, а при `accept` показывать серверную ошибку (`detail`) из `calls/answer`.
- Web-клиент должен иметь локальный TTL fallback по `expires_at` для автоматической остановки рингтона и скрытия incoming UI при задержке `call_ended`.
- Для web PWA при адресном звонке должен отправляться background push `type=call_invite`, чтобы пробуждать приложение и показывать входящий call сигнал в фоне.
- Для web PWA `call_invite` должен быть silent-push (без системного звука уведомления), чтобы исключить двойной звук и гонки с клиентским рингтоном.
- И mobile, и web обязаны игнорировать дубли входящего `call_invite` при совпадении `call_id`.
